# Model card — fair-football-fee `v1.0.0`

_Generated by `python -m src.ml.calibrate` from the JSON files in `artifacts/v1.0.0/`. Hand-written text states facts that don't change between runs._

## Model details

- **Type:** XGBoost gradient-boosted trees (`xgboost_regressor`), 781 trees, max depth 5, seed 42.
- **Trained:** 2026-10-29 on data version `2026-06-12_24ade17697` (git `81a8b4e`). Libraries: python 3.12.15, xgboost 3.4.1, lightgbm 4.7.0, scikit-learn 1.9.1, optuna 5.0.0, numpy 2.5.4, pandas 3.1.0.
- **Output:** an estimate of the player's Transfermarkt market value at date t, with an 80% and a 90% prediction interval and per-prediction TreeSHAP drivers.
- **Owner:** Gunnar (`gunnarwrld/fair-football-fee`), portfolio project.

## Intended use

- Explore what a Premier League player's recent playing record, output, age and fitness imply about their crowd-sourced market value, and how the estimate would change in a what-if scenario.
- A teaching and portfolio artifact for point-in-time feature engineering, honest evaluation and calibrated uncertainty.

## Out of scope

- **Transfer fees.** The target is the Transfermarkt crowd valuation, not a negotiated fee. Fees depend on release clauses, add-ons, contract length and negotiating leverage, none of which the model sees.
- Players outside the Premier League, or with fewer than 450 tracked minutes in the last 12 months.
- Contract decisions. The main model has no contract feature (contract dates can't be reconstructed point-in-time from open data), so it can't price an expiring contract.
- Any decision about a real person's career or pay.

## Data

- dcaribou/transfermarkt-datasets (CC0): valuations, appearances, games, transfers. salimt/football-datasets (no license): injuries and profiles. Both pinned by commit and SHA-256 in `data/raw/MANIFEST.json`.
- salimt-derived data is never redistributed, and raw injury records are never exposed by the API.
- Every feature uses source rows dated strictly before t; ongoing injuries are clipped at t. Verified by truncation invariance and train/serve parity tests.
- Population: Premier League snapshots with ≥ 450 tracked minutes in the prior 365 days and a club confirmed by match data. Rows: train 8,401 · val_tune 1,118 · val_calib 1,101 · test 1,288.

## Target

`ln((value + 1) / (M + 1))`, where M is the trailing-365-day median value of the same population (point-in-time). Predictions are converted back with the same M, so the model learns value relative to the league and doesn't have to extrapolate inflation.

## Evaluation protocol

- Splits by whole July–June cycles: train < 2023-07-01 ≤ val_tune < 2024-07-01 ≤ val_calib < 2025-07-01 ≤ test.
- Hyperparameters: Optuna with expanding-window CV inside train. Model choice on val_tune. Final model fit on train + val_tune. Intervals calibrated on val_calib. Test scored once per model version.
- Recentering and the interval method were chosen on a rolling backtest inside train and val_tune.

## Explanations

Exact TreeSHAP per prediction, shown as multiplicative effects vs a typical player. Largest drivers across current players: Age; Appearances, last 24 months; Goals conceded per 90, last 12 months; Minutes, last two completed seasons; Minutes, last 24 months. See `reports/phase4_explain_intervals.md`.

## Known limitations

- **Older players** are over-valued: the 32+ age band has MdAPE 62.3% and mean log bias -0.515 on test (Phase 3, before recentering). Transfermarkt depreciates age faster than output declines.
- **Low-value players**: the <5M bucket (by actual value) has MdAPE 131.4% (Phase 3). The lowest predicted-value bin gets a wider interval for this reason.
- **Update-round shocks.** Each Transfermarkt revaluation round can move the whole league. Recentering uses the latest completed round, so a sudden new shift is only absorbed one round later.
- **Coverage under drift.** Test coverage of the 80% interval is 77.0% (95% CI 73.7%–80.1%). Conformal guarantees assume calibration and test rows are exchangeable, and later seasons drift, so coverage is checked per batch and per bin in the Phase 4 report. Players who end up valued under €5M are covered least (53.0%).
- The recentering offset is computed from the latest Transfermarkt update round in the data, so it must be recomputed (`make calibrate`) whenever the data is refreshed; registration refuses a stale offset.
- Club data in older seasons is noisy; rows whose club can't be confirmed by match data are excluded (about 8% of train).

## Ethical considerations

- The players are real people. Estimates describe a crowd valuation, not a player's worth or ability, and the API and UI must label them that way.
- Injury history is used only as aggregated features; individual injury records are never shown or returned.

